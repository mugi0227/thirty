# 収益化の方針案

2026年10月12日に、下記の推奨どおり **無料・広告なし＋買い切りの Thirty+** に決めました。

## 決定と実装

| 項目 | 内容 |
| --- | --- |
| 無料 | タイマー、縦横のレイアウト、アクセスガイドの案内、クラシックのスキン。広告なし |
| Thirty+ | 買い切り（非消耗型）。製品ID `jp.mugilab.thirty.plus`。開発用の価格は¥480 |
| 現在の特典 | 5種類のスキン、ロック画面・StandBy・Dynamic Islandへの表示、終了音4種類、休憩をはさんだくり返し、棒60本、分だけの表示、アプリアイコン5種類 |
| 無料のまま | 始めやすくする機能（すぐスタート、ショートカット、コントロールセンター、ウィジェット）と終了画面。アプリの目的そのものなので課金の対象にしない |
| 試着 | スキン画面で、購入前にロックされたスキンを大きく表示して試せる |
| 案内 | 3回目のタイマー終了後に一度だけ、終了画面に小さく表示する。計測中や起動時には出さない |
| 復元 | スキン画面の「購入を復元」（`AppStore.sync`） |

実装は [Store.swift](../ios/Thirty/Store.swift)（StoreKit 2）、[Skin.swift](../ios/Thirty/Skin.swift)、[SkinPicker.swift](../ios/Thirty/SkinPicker.swift) です。
Xcodeでの実行時は [Thirty.storekit](../ios/Thirty.storekit) を使い、App Store Connectなしで購入を試せます。
配布する前に、App Store Connectで同じ製品IDの非消耗型App内課金を作成し、価格を決める必要があります。

## 検討した内容

広告で稼ぐ形は、このアプリとは相性がよくありません。

## 広告が合わない理由

- アプリの目的は「SNSなどから離れて集中すること」です。計測中に広告を見せると、その目的と真っ向から衝突します。
- 終了時のインタースティシャル広告は、達成した瞬間を「待たされる体験」に変えてしまいます。次も使おうという気持ちを最も削る場所です。
- アクセスガイドで画面を固定していると、広告をタップしてもSafariやApp Storeに移れません。クリック収益はほぼ期待できず、誤タップの不満だけが残ります。
- 1回30分で1日に数回開く程度のタイマーは、表示回数が少なく、広告単価を考えると収益は小さい見込みです。
- 広告SDKを入れると、トラッキング許可のダイアログ、プライバシー表示の追加、通信が増えます。「通信なし・アカウントなし」という今の分かりやすさも失います。

## 推奨する形

| 項目 | 内容 |
| --- | --- |
| 無料版 | タイマー、縦横のレイアウト、アクセスガイドの案内など、今の機能はすべて無料。広告なし |
| Thirty+（買い切り） | 数百円程度。液晶の配色（バックライトの色など）、よく使う時間の保存、ロック画面やDynamic Islandでの残り時間表示、ウィジェットなど「あると嬉しい」もの |
| 案内のタイミング | 3回目か5回目のタイマー終了時に、一度だけ控えめに紹介する。計測中や起動直後には出さない |

「先に有料で買ってもらう」形は、知らない人が試す入口がなくなるので、このアプリの規模では不利だと考えます。
「気に入ったら課金する」というご自身の感覚の方が合っています。投げ銭（Tip Jar）だけ置く方法もありますが、何が手に入るかが明確な買い切りの方が購入されやすいです。

どうしても広告を入れる場合は、待機中の画面の下部に小さなバナーだけにし、計測中と終了直後には出さないことを条件にしてください。
